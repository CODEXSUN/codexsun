# Zuno: core business and ownership

Super Admin development diagnosis, conversations, cases and operational watch.

## Ownership boundary

Zuno is a privileged development/operations devkit, not a tenant business app. It reads repository baseline docs, not another tenant's overrides.

## Inputs and outputs

- Configure the authorised source checkout, logs and model provider.
- Choose work mode and open a diagnostic conversation/case.
- Read bounded source/log/watch evidence through named tools.
- Search developer reference pages and cite the source path before proposing a change.
- Review plans and controlled correction workflows; never infer deployed state from repository text.

## Extension rules

Keep new entities, validation, routes, migrations, permissions and UI inside `devkits/zuno` or the external owner contract. Use public lookups for parent identities. Register app/tenant scope through Platform composition; never copy parent private implementations.

## Data and authority

Repository pages describe code. Tenant metadata and overrides are isolated to the signed tenant database. Developer prose is evidence for review, not authority to run database or external actions. Confirm the installed version, source provider and current permissions before relying on a business result.
