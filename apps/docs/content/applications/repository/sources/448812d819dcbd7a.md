```markdown
# Codeit agent handbook

This folder defines the future Codeit agentic development workspace.
Humans, Antigravity, OpenCode, and other coding agents can use the same packets.
These documents do not activate tools, grant permissions, or authorize implementation.

## Start here

1. Read root `AGENTS.md`, `assist/AGENT-GUIDE.md`, and `assist/governance/rules.md`.
2. Read `devkits/codeit/README.md` and this folder's PLAN.md, TASK.md, and SKILLS.md.
3. Read [PRODUCT.md](PRODUCT.md), [ARCHITECTURE.md](ARCHITECTURE.md), and [DECISIONS.md](DECISIONS.md).
4. Read [SUPERVISOR-WORKERS.md](SUPERVISOR-WORKERS.md) and your role in `roles/`.
5. Read your packet in `tasks/` and its linked contracts.
6. Confirm the latest user authorization before changing implementation files.

## Use the plan

The supervisor selects one authorized milestone and creates bounded worker assignments.
Each worker gets one packet, base revision, allowed files, dependencies, and acceptance criteria.
The reviewer independently checks the diff and evidence.
The supervisor integrates accepted work and runs combined verification.
Use [IDE-HANDOFF.md](IDE-HANDOFF.md) for starting prompts.
Use [DEVELOPMENT-LOOP.md](DEVELOPMENT-LOOP.md) for implementation.
Use [E2E-VERIFICATION.md](E2E-VERIFICATION.md) before declaring the product ready.

## Status and folder map

Packet states are `planned`, `ready`, `running`, `waiting`, `blocked`, `review`, `verified`, and `done`.
Every future packet starts as `planned`.
`verified` requires checks on an identified revision. `done` also requires integration and review.
Historical shell evidence does not establish future feature completion.

Top-level documents define the product, contracts, rules, and acceptance strategy.
`roles/` defines supervisor, worker, and reviewer responsibilities.
`tasks/` contains independently assignable implementation packets.
`templates/` contains dispatch, handoff, and evidence forms.
Runtime logs and worker output belong outside Git in configured Codeit storage.
```
