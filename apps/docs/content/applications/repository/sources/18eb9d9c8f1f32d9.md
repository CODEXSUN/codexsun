# Codeit architecture

Status: proposed. T00 freezes concrete contracts before workers start.

## Runtime topology

Retain the current web application on port 7070 by default.
Propose one Codeit local runtime on loopback port 7071 during authorized implementation.
The browser uses same-origin `/api/codeit` through a development proxy or production host.
The runtime owns persistence, provider credentials, tool policy, process supervision, and events.
It must start without Platform, MariaDB, or another business app.

Proposed settings are `CODEXSUN_CODEIT_API_PORT` and `CODEXSUN_CODEIT_STORAGE_ROOT`.
They are planning names, not implemented configuration.
T00 checks ports before accepting them.
Production packaging serves static web assets and the API through one trusted local surface.
Development may use separate ports with a strict proxy.
Opening from Platform is navigation, without silent cookie, token, or tenant sharing.

## Source and module ownership

Retain `devkits/codeit/src` for the frontend.
Propose an API workspace at `devkits/codeit/api`, using `@codexsun/codeit-api` and the repository version.
Use root npm workspaces, one dependency tree, and root-only build output.
Create source directories only when their executable behavior exists.

| Leaf            | Owns                                                  | Public use                             |
| --------------- | ----------------------------------------------------- | -------------------------------------- |
| project         | Root trust, repository identity, settings             | Authorized project handle              |
| conversation    | Threads, messages, context references                 | Conversation operations                |
| run             | State, budgets, events, supervisor/worker assignments | Start, cancel, resume, inspect         |
| provider        | Model capabilities, streaming, usage                  | Typed provider adapter                 |
| tool            | Definitions, policy, grants, invocations              | Authorize and invoke a capability      |
| workspace       | Files, patches, commands, Git inspection              | Already-authorized workspace operation |
| artifact        | Plans, diffs, diagnostics, reports, evidence          | Versioned artifact storage             |
| plugin          | Manifests, lifecycle, revocation                      | Reviewed adapter capability            |
| personalization | Facts, provenance, preferences, retention             | Permitted context projection           |
| overview        | Introduction and runtime scope                        | Existing read-only exports             |

Composition roots register public contracts and lifecycle order only.
Each entity keeps storage, validation, routes, and UI in its owner.
Workspace adapters execute operations. They do not own run policy or sibling schemas.
Codeit orchestrates development work without becoming a generic business CRUD engine.

## Persistence

Use an embedded local store for the first single-operator product.
SQLite is the proposed default, subject to T00 adapter and packaging checks.
Keep adapters at persistence boundaries. Do not build a generic entity repository.
Commit metadata and events transactionally. Store large artifacts under the private storage root.
Artifact records contain hash, size, media type, relative object key, and retention class.
Reject browser-supplied absolute artifact paths.

Use internal integer IDs and unique eight-character lowercase hex `uuid` values for externally referenced records.
Handle UUID collisions with a unique index and bounded regeneration.
Authorization tokens are separate high-entropy secrets. A public UUID never grants access.
Use owner-prefixed tables, timestamps, lifecycle fields, versioned migrations, and the `migration_schema` ledger.
Document SQLite differences from MariaDB. Tenant mode must retain tenant-database isolation.

## Local trust boundary

Loopback binding alone is insufficient authorization.
Verify exact Host and Origin values. Reject rebinding hosts and unapproved origins.
Use a bootstrap/pairing flow that proves possession outside arbitrary web content.
Bind sessions and grants to the operator and project. Protect mutations against CSRF.
Use HttpOnly sessions. Never put credentials or session bearer tokens in browser storage.
Cookies are not isolated by port. Use distinct Codeit cookie names and reject other localhost app sessions.
Authenticate event streams and check their origins.
Recheck policy at dispatch and invocation time.

## Execution isolation

An allowlisted path does not make shell execution safe.
Require an OS-enforced runner boundary for mutation and command capabilities.
T00 must prove the selected Windows isolation method before enabling them.
Without that boundary, ship read-only mode and mark Work unavailable.
Use explicit working directories, bounded output, timeouts, process-tree cancellation, and network policy.
Separate processes alone do not constitute a sandbox.

## Scaling

Begin with one runtime, one embedded-store writer, and a bounded local worker pool.
Persist the queue before adding distributed infrastructure.
Add event backpressure, artifact quotas, retention, and configurable concurrency before raising worker counts.
Remote workers need authenticated transport, contract compatibility, independent grants, and correlated audit events.
Add tenant-aware isolation if remote work involves tenants.
Do not introduce microservices, Redis, or a generic workflow engine without measured need and approved ownership.
