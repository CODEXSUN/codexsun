# Frappe plan

## Scope

Customer import now sources `Mobile Contact Customer` and validates its `Mobile Contact` and `Customer` references.
Customer identity is connection-scoped, not phone-scoped. Core stores the Frappe document name as the contact code through `resolveExternalContactForDatabase`; Frappe stores the connection-scoped source mapping separately.
See the README for source fields, existing-data compatibility, and test commands.

Verified external connections, user mappings, imports, exports, and approved CRM integration workers.

## Ownership contract

Use the public verified connection contract. Resolve tenant credentials server-side. Queue retryable transfers and preserve parent mapping, idempotency, and audit behavior.

The root Agent Guide and governance rules remain authoritative.
Keep one root dependency installation, lockfile, and generated output tree.
Keep business roles inside their owner and compose other components through public contracts.

## Current source surfaces

- `api/src/modules`: `activity-import`, `call-log-sync`, `connection`, `contact-import`, `crm-duty-sync`, `enquiry-sync`, `export`, `live-sync`, `user-mapping` (including identity audit), `user-sync`.
- `web/src/modules`: `activity-import`, `call-log-import`, `connection`, `contact-import`, `data-source`, `enquiry-sync`, `export`, `live-sync`, `overview`, `user-mapping` (including identity audit), `user-sync`.

Source presence is not release evidence. Confirm executable behavior before describing a capability as complete.
