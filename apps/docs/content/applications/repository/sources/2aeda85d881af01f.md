# Frappe plan

## Marketing integration planning — 2026-10-23

Status: design only. No runtime capability or provider access is added.
See [Marketing Phase 0](../../marketing/agent/PLAN.md#phase-0-decisions-and-contract-review), gap G12, delivery phase 1.

Marketing does not add a Frappe read source, Campaign export, Consent export, or new outbound capability.
Preserve current tenant-specific verified connection, inbound/bidirectional direction, mappings, and approved transfer scopes.
Marketing intake could create CRM records that enter existing enquiry outbox logic.
Define a source-aware export policy before enabling Marketing-to-CRM intake. Default new Marketing-origin export to blocked until explicitly approved.
Do not silently modify the existing exports for current records. Record origin and suppress integration echo loops.
Provider permission or Marketing activation never grants remote Frappe write authority.

## Scope

Enquiry live sync supports inbound-only delivery and optional bidirectional automatic export.
The initial run imports history. A successful source checkpoint governs later polling and recovery.
Retain complete source revisions before mapping, and preserve CRM-only fields during inbound updates.
See the README for direction behavior, data coverage, and verification limits.

Customer import now sources `Mobile Contact Customer` and validates its `Mobile Contact` and `Customer` references.
Customer identity is connection-scoped, not phone-scoped. Core stores the Frappe document name as the contact code through `resolveExternalContactForDatabase`; Frappe stores the connection-scoped source mapping separately.
See the README for source fields, existing-data compatibility, and test commands.

Verified external connections, user mappings, imports, exports, and approved CRM integration workers.

## Ownership contract

Use the public verified connection contract. Resolve tenant credentials server-side. Queue retryable transfers and preserve parent mapping, idempotency, and audit behavior.

The root Agent Guide and governance rules remain authoritative.
Keep one root dependency installation, lockfile, and generated output tree.
Keep business roles inside their owner and compose other components through public contracts.
