# Frappe enquiry sync

`apps/frappe/api` owns the Frappe connector, and `apps/frappe/web` owns its tenant workspace. CRM enquiries remain in the tenant's local `crm_enquiries` table; CRM list and detail reads never call Frappe.

The connector uses the same site URL and token authentication shape as TechMedia: a base URL, API key, and API secret. An admin can save these settings on `/app/frappe/connection`. The API encrypts credentials in the tenant database using a key derived from the Platform `JWT_SECRET`; keep that secret stable or re-enter credentials after rotation. Credentials are never returned by the API. The existing `CODEXSUN_FRAPPE_ENABLED`, `CODEXSUN_FRAPPE_BASE_URL`, `CODEXSUN_FRAPPE_APP_KEY`, and `CODEXSUN_FRAPPE_APP_SECRET` values remain a fallback until a tenant connection is saved.

Enable both CRM and Frappe for the tenant. The Frappe connection page provides Save and Verify actions. Blank credential fields preserve stored values. Verify can test edited values before Save; only an unchanged saved connection updates the saved verification state. The seeded `frappe.connection.manage` permission grants Save and Verify to tenant admins. `GET /frappe/connection` exposes only configuration flags and status to CRM enquiry viewers. `/app/frappe/overview` shows local enquiry counts, a searchable record table, posted state, and per-record Sync actions. Posted counts mean a remote document name is stored; compare Local updated and Last post to spot edits that need another post. `GET /frappe/overview` reads local records and counts. `POST /frappe/enquiries/:id/sync` posts a local enquiry to Frappe's `Enquiry` DocType the first time and updates the returned document name on later calls. `GET /frappe/enquiries/:id/sync` reads the local sync result. Ordinary CRM list and detail reads use only local data.

`/app/frappe/enquiry-sync` supports manual transfers in both directions. From Frappe previews remote Enquiry records with `GET /frappe/enquiries/remote`; To Frappe lists local records. Both lists support row selection and a select-all checkbox for the currently shown records. Pulling a selected remote ID through `POST /frappe/enquiries/pull` rechecks that document and creates or updates a local CRM enquiry through CRM's service. The remote ID is kept in `frappe_enquiry_sync` so later pulls do not create another local record. A pull rejects a locally created record and rejects a Frappe-origin record changed locally since its last sync. Unmatched CRM status or priority and remote records without a mobile or customer are reported per record. Posting selected local IDs uses the existing outbound endpoint. The page reports each failed record after a batch. Remote preview requires Frappe connection management and CRM view-all permission; pull also requires CRM create and update permission.

`/app/frappe/users` previews enabled Frappe System Users through the saved connection. The preview reads Frappe Users and Employees when opened or refreshed, matches `Employee.user_id` to the Frappe user, and displays the Employee document name as its employee code. Active Employee links take precedence when a user has multiple Employee records. It also compares email addresses with local tenant users. `POST /frappe/users/import` rechecks the selected remote user and asks Platform's tenant-user service to create a local account with the standard User role. Add user defaults to a generated temporary password, shown once after creation. The operator can instead enter and confirm a custom password before creation; the API does not return that custom password. Existing local email addresses are reported without changing those accounts. Preview requires Frappe connection management and local user view permission; import also requires local user creation and role assignment permission. There is no background user sync or Frappe login bridge.

`/app/frappe/user-mapping` pairs an existing local application user with an enabled Frappe System User. The `frappe_user_mappings` table stores one remote user and its Employee code per local user in the tenant database, and a unique key prevents assigning the same remote user to two local users at one Frappe site. Save rechecks the remote identity and Employee link before writing. A changed Frappe site marks old mappings for review; users can replace or remove them. When a local enquiry is first posted, its creator's current mapping supplies the optional `user_employee` field. On pull, that Employee code assigns the local enquiry to its mapped active application user when available. Later posts preserve the original Frappe owner. Mapping does not copy passwords, sessions, roles, or permissions, and does not provide Frappe single sign-on.

The tenant migration creates `frappe_connection_settings` and `frappe_enquiry_sync` when CRM and Frappe are enabled. Run tenant migrations and seed permissions before calling the connection or sync routes. The target Frappe site must have TechMedia's `Enquiry` DocType and compatible `title`, `enquiry_details`, `mobile`, `date`, `due_date`, `priority`, and `status` fields. Status and priority names are copied from local CRM, so configure matching values on the target site. A Frappe rejection leaves the local enquiry intact; retry the sync after fixing the target or connection.

The tenant Live Sync setting schedules enquiry exports and incremental imports through the Platform queue. Outbound batches select new enquiries and local edits newer than their saved sync time; inbound polling replays a 24-hour `modified` window and skips records already synced at an equal or newer Frappe timestamp. The worker requires the existing Platform queue worker and Redis configuration. Queue retries are limited; a first POST that succeeds remotely but fails before `frappe_enquiry_sync` is saved can still create a duplicate because the target DocType has no stable CRM source identifier. Frappe creates the remote system `creation` timestamp; outbound CRM business date maps to the Enquiry `date` field. Live deployment and remote readback must be verified before this source behavior is treated as active in production.
