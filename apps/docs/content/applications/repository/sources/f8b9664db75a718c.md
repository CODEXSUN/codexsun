# Data Migration

Super Admin DevKit for visual, audited transfers from a saved external MariaDB source to a registered active CODEXSUN tenant MariaDB database. Platform owns authentication, destination tenant lookup, and destination database secret resolution. This DevKit owns encrypted external source connections, previews, table copying, and the `data_migration_runs` master ledger.

The Overview, Migration, and Migration Settings pages are under the Super Admin Database menu and linked from Super Admin Apps. A Super Admin uses Migration Settings to enter or update an external source's host, port, user, password, and TLS mode. Database is the last, optional field. The connection is tested and saved before the page fetches its accessible databases. The database list hides MariaDB system databases and the configured Platform master database. A Super Admin selects a database and saves the source again before starting a migration. An edited connection can keep its stored password by leaving the password field blank. The Migration page selects a configured source, one registered destination tenant, and one table. External passwords are encrypted with an application secret before storage in the Platform master database; they never return to the browser. Preview compares ordered column names, types, nullability, and generated attributes and reports row counts. Copy requires an empty destination table and limits a run to 10,000 rows. It writes one destination transaction, so a failed insert rolls back copied rows. Tables must already exist at the destination; the tool does not apply schema migrations. Foreign key dependencies must be copied in valid order.

Migration Settings offers searchable choices from saved source names, hosts, databases, users, and ports. Port choices also include 3306 and 3307. Each choice has a Create option for a new value. Choosing a saved source name fills its public connection details. After a connection is saved, the Database choice also shows databases returned by that connection. The password is never suggested or filled.

Migration Settings also offers the current Platform MariaDB server as a source preset. The server returns only its host, port, and user for display. When selected, the API tests the connection and stores its password encrypted; the password is never sent to the browser. The source starts without a selected database, and the configured Platform master database remains excluded from database discovery and migration.

External source connections require verified TLS by default. Super Admin can explicitly choose Disabled for a source that does not support TLS. The destination uses the registered CODEXSUN tenant connection policy.
The encrypted source password depends on the Platform `JWT_SECRET`; preserve that secret or re-encrypt saved source connections during key rotation. A saved source can be verified or disabled without removing its run history. Remove erases the saved password and deactivates the connection while retaining migration run history.

This is a bounded table-copy workflow, not ongoing bidirectional sync. The source is a saved external MariaDB connection; the destination is a registered tenant database. The tool rejects source and destination connections that resolve to the same host, port, and database. This feature does not copy the Platform master database.

## Verification

From the repository root run `npm run typecheck -w @codexsun/data-migration-api`, `npm run typecheck -w @codexsun/data-migration-web`, `npm run lint -w @codexsun/data-migration-api`, `npm run lint -w @codexsun/data-migration-web`, and the Platform API/web checks. Verify fresh and existing master migration, a real two-database transfer, denied access, rollback, and browser navigation before production use.

`npm run test:e2e:data-migration` uses configured local MariaDB credentials to create three uniquely named disposable schemas. It checks the tracked source and ledger migration, encrypted source setup, preview, copy, repeat-copy rejection, failed-insert rollback, and denied API access, then removes those schemas.
