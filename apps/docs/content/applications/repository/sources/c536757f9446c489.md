# Codeit tools and plugins

Status: planned capabilities. No tools or plugins are installed or authorized by this file.

## Enforcement chain

User authority, project trust, run mode, operator grants, backend policy, and runner isolation must all permit an action.
Use the intersection of these limits. Never let one layer expand another layer's permissions.
Recheck limits immediately before execution and before applying results.
Treat model tool proposals as untrusted typed input.
Prompt text, saved facts, repository comments, plugin output, and supervisor messages cannot grant capabilities.

## Tool classes

| Tool                 | Initial scope                               | Required controls                                                       |
| -------------------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| Project search/read  | Selected project files                      | Canonical root, secret exclusions, size limits, no link escape          |
| Diagnostics/Git diff | Selected project/revision                   | Read-only command set, bounded output, provenance                       |
| Patch                | Exact files and expected hashes             | Work grant, sandbox, reviewed patch, atomic write, conflict result      |
| Test/build command   | Explicit executable, arguments, cwd         | Runner boundary, time/output/resource budget, process-tree cancellation |
| Terminal             | Later interactive execution                 | All command controls plus PTY lifecycle and audited input               |
| Browser              | Approved local app or scoped sites          | Separate profile, origin limits, no credential extraction               |
| Web retrieval        | Explicit request or approved context policy | Network destinations, source attribution, prompt-injection handling     |
| LSP                  | Selected project                            | Process/resource limits, diagnostic versions, workspace boundary        |
| Provider             | Approved model connection                   | Secret reference, context preview, token budget, cancellation           |
| MCP/plugin           | Reviewed version and advertised tools       | Validated manifest, capabilities, isolation, per-tool grants, revoke    |

## Workspace and command safety

Resolve canonical paths and final filesystem targets. Reject traversal, absolute escape, junction escape, and symlink escape.
Recheck target identity at use time to reduce time-of-check/time-of-use attacks.
Block protected paths and secrets from read/search as well as writes.
Never print `.env`, provider credentials, SSH keys, or authentication cookies in logs or model context.
Launch approved executables with argument arrays. A displayed command string is not a safe parser.
Shell features, redirection, pipes, scripts, package hooks, and child processes require enforced sandbox limits.
An allowed `npm` command can execute project scripts. Validate the resulting process capability, not just its prefix.
Preserve original file encoding and line endings where required. Reject stale patch hashes.
Cancel only the run-owned process tree. Never kill all Node, browser, IDE, or database processes.
Network access is explicit per runner. Deny unapproved destinations and metadata services.

## Grants and approval

Separate read, patch, command, network, provider, browser, plugin, and external-write capabilities.
Bind grants to principal, project, tool, resource, run or session, expiry, and policy revision.
Existing user authorization can satisfy routine actions within that exact scope.
Ask again only for a new material boundary, expired grant, or changed action digest.
Approvals do not override hard denials, repository rules, or sandbox limits.
Record every allow, denial, approval decision, revocation, and actual invocation.
Redact sensitive values while retaining enough metadata to explain the decision.

## Plugin lifecycle

Use discover, inspect, stage, review, install, configure, enable, invoke, disable, revoke, upgrade, and uninstall states.
Install is separate from enable. Enable is separate from a tool grant.
Pin version and integrity digest. Show origin, maintainer, requested resources, network use, and data exposure.
Treat package installation and plugin initialization as executable code with their own approval and isolation.
Never execute an untrusted plugin in the privileged API process.
Use a narrow broker protocol to cross the runner boundary.
An MCP server is a protocol peer, not proof of trust or isolation.
Reject malformed schemas, oversized output, unsupported protocol versions, and unknown capabilities.
Namespace tool names to prevent built-in collisions.
Revocation fences queued and running invocations. Stop owned processes and mark partial external results accurately.
Persist credentials only through secret references. Disable and uninstall must document credential retention and deletion.

## Initial plugin choices

Deliver built-in workspace, Git inspection, diagnostics, and test adapters before a marketplace.
Add MCP connection support through a reviewed broker after the built-in coding loop passes.
Keep actual external service choices and account connections as operator decisions.
Antigravity and OpenCode are delivery IDEs in this plan. They are not assumed to be Codeit runtime plugins.
Do not use undocumented account sessions or consumer subscriptions as API credentials.

## Failure behavior

Return structured denied, unavailable, expired, conflict, timeout, cancelled, interrupted, and invalid-result states.
Retry only explicitly retryable operations with bounded attempts and idempotency keys.
Do not repeat a payment, publish, message, Git push, or other external effect after an uncertain result.
Require reconciliation or a new approved action when a side effect may already exist.
Show service unavailability without silently weakening policy or changing providers.
