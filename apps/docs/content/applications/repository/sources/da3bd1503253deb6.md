# Supervisor and worker protocol

Status: planned runtime behavior and implementation delivery protocol.
The current request does not authorize starting workers in either IDE.

## Roles

The supervisor owns scope, contract freeze, dependency scheduling, grants, leases, integration, and final reporting.
Workers own one assigned packet within explicit paths and budgets.
The reviewer examines diffs and evidence independently from the producing worker.
One integrator owns shared composition files and final combined verification.
An agent can fill several roles sequentially, but cannot accept its own unreviewed completion claim as independent review.

Read [roles/SUPERVISOR.md](roles/SUPERVISOR.md), [roles/WORKER.md](roles/WORKER.md), and [roles/REVIEWER.md](roles/REVIEWER.md).

## Dispatch protocol

1. Confirm the human-authorized milestone and preserve current dirty changes.
2. Record base revision, working-tree fingerprint, requirements, and contract revision.
3. Select dependency-ready packets from TASK.md.
4. Create a dispatch record using [templates/DISPATCH.md](templates/DISPATCH.md).
5. Grant disjoint paths and bounded tools, resources, attempts, and deadlines.
6. Start workers only after each accepts scope and lease conditions.
7. Collect evidence and review changes before integration.
8. Verify the combined revision and close the packet ledger.

Do not put secrets into dispatch prompts.
A task dependency is satisfied only by its accepted artifact revision and required passed checks.
The mere existence of a branch or a worker final message is insufficient.

## File ownership and workspaces

Prefer separate managed worktrees or equivalent isolated checkouts when the authorized host supports them.
Respect repository rules for one root dependency tree and generated output.
T00 must validate how isolated checkouts resolve dependencies without nested installations.
If that cannot be proved, use one checkout with disjoint file leases and serialize mutations.
Parallel planning and read-only review remain possible when implementation must be serialized.

The supervisor records exact allowed files before dispatch, not only broad module labels.
No two active workers may write the same file.
Reserve root package files, lockfiles, global styles, public exports, routing, and boundary rules for the integrator.
Workers submit required shared changes as a typed change request.
New files use a leased directory with explicit ownership.
Workers do not alter Git indexes, reset other changes, or clean another worker's files.

## Leases, fencing, and budgets

Each assignment has worker ID, lease generation, expiry, heartbeat, attempt, and allowed paths.
Renew a lease only while the worker remains authorized and within budget.
Expired or superseded generations cannot apply patches or report accepted success.
Use per-run and per-worker time, token, tool, process, output, and artifact limits.
Default to at most two implementation workers for the first runtime release.
Raise concurrency only after resource and conflict tests pass.
Workers cannot spawn more workers unless the supervisor explicitly creates a separate assignment.

## Completion and review

A worker returns a handoff, diff/base identity, changed paths, test commands, exit codes, artifacts, and limitations.
The supervisor validates path ownership and patch preconditions before accepting the handoff.
The reviewer checks correctness, permissions, tests, architecture, failure handling, and unsupported claims.
Accepted worker checks become stale when relevant integration inputs change.
The integrator reruns affected checks after combining patches.
Resolve conflicts against current content. Never overwrite a newer file to match an old worker patch.

## Failure and cancellation

Worker crash or lost heartbeat marks the assignment interrupted and revokes its lease.
Retry creates a new attempt after checking partial changes and external effects.
Do not have two attempts executing the same mutation concurrently.
Cancel the parent run by fencing dispatch first, then stopping its owned processes.
Queued tasks must not start after cancellation. Late results remain evidence without applying changes.
Pause retains durable state. Resume rechecks current inputs, grants, trust, and budgets.
A worker blocker includes the exact missing dependency, reproduction, attempted safe fixes, and next required action.

## Cross-IDE coordination

Use the same task ID, contract revision, base revision, lease, and handoff format in Antigravity and OpenCode.
Do not assume the IDEs share context, permissions, history, or worker state.
The supervisor ledger is the coordination source. Native IDE panels are views or transport surfaces.
If automatic cross-IDE dispatch is unavailable, a human transfers dispatch and handoff text.
Manual transfer is a supported delivery path, not an implemented API integration.
