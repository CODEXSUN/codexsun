# Runbooks

## Scope

Zetro now has a separate Runbooks module for recurring, refined local work.

## Flow

1. A user saves a title, prompt, repository, module scope, and run mode.
2. A one-time run starts only from Start now.
3. A repeating runbook includes an interval and stays disabled until the user enables it.
4. A manual or due schedule creates a separate Git worktree and branch.
5. Local Codex starts inside that worktree with a constrained instruction.
6. Zetro stores the worker report and the final run status.
7. The scheduler sets the next due time after each repeating run starts.

## API initiation and stop

Another Zetro module can initiate a saved runbook for one selected item. The
caller supplies its module ID and item ID. Zetro stores this initiator on the
run. A one-time initiation starts a run. A repeating initiation enables its
saved schedule. An active run has a Stop action that stops the local Codex
process and records a stopped report.

## Multiple runbooks

The Zetro Runbooks workspace uses a master-detail layout. The left pane lists
all saved items. The right pane shows a selected item or a new-item form.

## Boundaries

Runbooks own their SQLite definitions and run history. They reuse Coding Workers'
public Git worktree service. They do not create an Agent Task, commit, push,
open a pull request, merge, deploy, or delete a worktree.
