# Data Migration working rules

Read this DevKit README, TASK, and PLAN along with the repository Agent Guide and governance rules. Keep external source connection records, encrypted credentials, table transfer behavior, and run history in this DevKit. Use only the Platform host adapter for actor and registered destination tenant resolution. Enforce Super Admin access on every route. Accept external source credentials only through the validated connection setup route, encrypt them before storage, and never return them to the browser. Never accept destination credentials or database names from a browser request. Preserve existing destination rows and report real verification evidence separately from static checks.

Migration sessions own their generated UUID, source/destination snapshot references, table-pair child rows, and field-pair child rows. Resolve tenant relationships through Platform and use foreign keys for relationships owned in the Platform master schema. Treat saved row counts and database names as migration preflight snapshots. A job may write only after every source table is mapped and all target tables are empty; keep the source read only and write the destination batch atomically.

Batch runs require a persisted generated query plan and an explicit finalize action. The server must recompute the schema, row counts, and mapped source-data fingerprint before finalization and again before execution. Display only identifier-quoted query templates with placeholders; never accept SQL text from the browser. Sample checkbox state is not a row filter unless a separate persisted row-selection contract is implemented and verified.
