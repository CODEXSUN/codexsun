## 1. Module-Owned Persistence Architecture

The workspace access module now encapsulates its complete data lifecycle under `devkits/zetro2/api/src/modules/workspace-access/persistence/`:

| Component | File | Responsibilities |
| --- | --- | --- |
| **Zod Contracts** | `workspace-access-contracts.mjs` | Formal runtime validation for entities, inputs, updates, and queries across workspaces, memberships, grants, and audit logs. |
| **Checksummed Migration** | `workspace-access-migration.mjs` (`zetro2.workspace-access.001`) | Creates `zetro_workspaces`, `zetro_workspace_memberships`, `zetro_capability_grants`, and `zetro_access_audit_logs`. Validated with canonical SHA-256 checksum. |
| **Repeat-Safe Seeder** | `workspace-access-seeder.mjs` (`zetro2.workspace-access.seed.001`) | Seeds initial default workspace (`ws-default`) and Owner membership (`usr-admin`) idempotently without duplicating or throwing on repeated executions. |
| **Lifecycle Plan** | `workspace-access-lifecycle-plan.mjs` | Binds module ID `zetro2.workspace-access`, ordered migrations, and repeat-safe seeders for `PlatformCore` `MigrationRunner`. |
| **Repository** | `workspace-access.repository.mjs` (`WorkspaceAccessRepository`) | Pure repository isolating database queries behind typed methods: workspace CRUD, membership lifecycle, capability grants, and audit logging with automatic secret redaction. |
| **Store Factory** | `workspace-access-store.mjs` (`WorkspaceAccessStore`) | Manages SQLite (or MariaDB) connection provider, executes migration/seeder runner, and exposes repository and database controls. |

## 2. Invariants & Governance Rules Compliance

1. **Strict Line Limit Compliance:**
   - All persistence files are strictly below 200 lines, well below the 700-line ceiling in `assist/governance/coding-agent-rules.md`.
2. **SHA-256 Checksum Integrity:**
   - Both migration `zetro2.workspace-access.001` and seeder `zetro2.workspace-access.seed.001` compute deterministic SHA-256 checksums via `createLifecycleChecksum` from `@codexsun/platform-core`.
3. **Repeat-Safe Idempotent Seeders:**
   - Verified that repeated execution of `store.initialize()` succeeds cleanly with 0 duplicate records.
4. **Secret Redaction in Audit Logging:**
   - `WorkspaceAccessRepository.recordAuditLog` dynamically inspects and redacts any configured credentials, tokens, and secrets before writing to the audit log table.
5. **No Private Cross-App Imports:**
   - All persistence and migration abstractions use `@codexsun/platform-core` and local module files only.
