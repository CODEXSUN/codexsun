## Artifact destinations

- `dist/zetro2/editor/` — packaged server root written by the default `export`
  stage through `docker build --target export --output type=local,dest=…`.
- No build output is written under `devkits/zetro2/zvcode/` on the host;
  host-side installs inside `zvcode/` remain prohibited.

## Container preparations (in-image only)

`postinstall` expects git metadata and two selfhost extension directories that
the import correctly excluded. The `source` stage creates them inside the
container only (not on the host):

- `git init` + `git config pull.rebase merges` + `blame.ignoreRevsFile`
- stub `package.json`/`package-lock.json` for
  `.vscode/extensions/vscode-selfhost-import-aid` and
  `vscode-selfhost-test-provider` (both absent from the upstream reference tree).

## Limitations

- The `deps`/`build`/`export` stages were not executed under this task; the
  full compile and artifact version read belong to task 2.8.
- Builtin extension downloads and Electron/Node header fetches require network
  at build time and are not vendored.
- Dockerfile-specific ignore file applies only when building with
  `-f devkits/zetro2/.container/Editor.Dockerfile` (BuildKit); raw
  `docker build` without `-f` would not use it.
- Rollback image retention and runtime wiring remain Phase 2 tasks 2.9c–2.10.
