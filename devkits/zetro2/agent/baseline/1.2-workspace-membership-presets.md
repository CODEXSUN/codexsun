## 1. Canonical Role Preset Hierarchy

The 5 role presets are strictly ranked and assigned specific administrative or operational privileges:

| Role Preset | Rank | Title | Description | Administrative |
| --- | :---: | --- | --- | :---: |
| **Owner** | 100 | Workspace Owner | Full administrative control, workspace settings, member management, secrets, and all agent/runtime capabilities. | Yes |
| **Maintainer** | 80 | Maintainer | Project configuration, MCP integration management, full developer capabilities, and agent execution. | No |
| **Developer** | 60 | Developer | Active coding, running tasks and agent sessions, creating commits, direct editing, and browser previews. | No |
| **Reviewer** | 40 | Code Reviewer | Read-only repository access, proposing review comments, inspecting diffs, and approving proposed changes. | No |
| **Viewer** | 20 | Observer / Viewer | Read-only inspection of workspace files and status without execution, editing, or approval permissions. | No |

## 2. Membership Invariants & Assignment Rules

1. **Hierarchy Assignment Rule:**
   - An actor can only grant, invite, or assign a role strictly below their own rank:
     ```javascript
     canAssignRole(actorRole, targetRole) // true iff actorRank > targetRank
     ```
   - Only `Owner` (Rank 100) can grant `Maintainer` (Rank 80), `Developer` (Rank 60), `Reviewer` (Rank 40), or `Viewer` (Rank 20).
   - `Maintainer` cannot grant `Maintainer` or `Owner`.
2. **Membership Management Privilege:**
   - Only `Owner` has the `workspace.admin` and `membership.manage` capabilities.
3. **Data Schema Validation:**
   - `workspaceSchema`: enforces positive timestamps, slug format (`^[a-z0-9-]+$`), and non-empty owner.
   - `workspaceMembershipSchema`: enforces valid role preset, non-empty workspace ID, user ID, and granting actor ID.
