## 2. Invariants & Security Guardrails Enforced

1. **Exact 5-Dimensional Binding:**
   Every approval is locked to:
   - **Exact Action:** (e.g. `change.apply`, `computer.use`, `command.execute`).
   - **Exact Actor:** The specific user ID requesting the execution.
   - **Exact Workspace:** The specific workspace where the action takes place.
   - **Exact Target Resource:** The file path, command string, or peripheral target.
   - **Cryptographic Content Digest:** SHA-256 hex digest of the payload/patch.
2. **Tamper Prevention:**
   - Any modification to the payload (even 1 bit or whitespace change) changes the SHA-256 digest, triggering an immediate rejection.
3. **Replay & Multiple-Execution Prevention:**
   - Approvals are one-time use tokens. Upon verification, the status transitions to `consumed` with `consumed_at` recorded. Subsequent attempts fail immediately.
4. **Actor & Cross-Workspace Isolation:**
   - Rejects actor substitution (User B attempting to consume User A's approval).
   - Rejects cross-workspace replay (attempting to consume Workspace A's approval in Workspace B).
5. **Enforced Expiration Windows:**
   - Approvals expire after their configured TTL. Stale approvals cannot be decided or consumed.
6. **Decision Authorization:**
   - Approvals can only be decided (approved/rejected) by workspace members holding the `change.approve` capability (Owners, Maintainers, Reviewers, or Developers with granted capability; Viewers are rejected with 403 Forbidden).
