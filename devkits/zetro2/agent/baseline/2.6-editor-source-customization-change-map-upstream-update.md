## Direct customization structure

Zetro2 owns `devkits/zetro2/zvcode` and customizes it directly (no pinned
upstream image). Intentional edits are organized by the four custom layers
from baseline 0.6: (1) Product, (2) Access, (3) Chat, (4) Runtime bridge.
Each change-map row records path, layer, reason, risk, and verify command.
Planned-but-unapplied layer work (telemetry, welcome screen, status bar,
access/chat/bridge) is listed under "Planned layer register" so task 2.7 and
later land in the map when they become real edits.

## Upstream source-update procedure (optional)

Documented in `upstream-update-procedure.md`. Adoption is an explicit
maintenance choice, never automatic. The procedure is reference-tree and
checksum based: snapshot → stage new reference → compute new diff → re-apply
each change-map entry → update provenance → run
`verify-zvcode` / `--diff` / `check-change-map` → rebuild via
`.container/build-editor.ps1` → compatibility checks (task 12.11) → adopt or
roll back to the prior image. The inherited `zvcode/scripts/sync-with-upstream.sh`
Git-rebase script does not apply (no `.git` in either tree, yarn vs npm) and
must not be run as-is.
