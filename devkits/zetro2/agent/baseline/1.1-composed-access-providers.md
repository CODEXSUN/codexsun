## 1. Composed Providers Overview

Task 1.1 establishes the core access foundation in `devkits/zetro2/api/src/modules/workspace-access/`:

| Provider Component | Implementation File | Public Dependency / Integration | Security & Isolation Boundary |
| --- | --- | --- | --- |
| **Secrets Provider** | `secrets-provider.mjs` (`ZetroSecretsProvider`) | Public environment variables & configuration | Extracts secrets from `process.env` (e.g. `ZETRO2_JWT_SECRET`, `PLATFORM_JWT_SECRET`); automatically redacts sensitive strings from error messages and logs; prevents credential leakage. |
| **Storage Provider** | `storage-provider.mjs` (`ZetroStorageProvider`) | Node `fs` & repository storage architecture | Isolates persistence strictly under `storage/apps/private/zetro2/` (`database.sqlite`, `sessions/`, `memory-bank/`); enforces runtime security checks preventing path traversal or escaping the app boundary. |
| **Identity Provider** | `identity-provider.mjs` (`ZetroIdentityProvider`) | `@codexsun/platform-core` (`createPlatformJwtToken`, `verifyPlatformJwt`, `readPlatformJwtClaims`) | Generates and verifies cryptographic HMAC-SHA256 JWTs; encapsulates 5 role presets (`Owner`, `Maintainer`, `Developer`, `Reviewer`, `Viewer`) and capability checks (`hasCapability`, `checkAuthorization`). |
| **Session Provider** | `session-provider.mjs` (`ZetroSessionProvider`) | Native crypto UUIDs & injectable deterministic clock | Tracks session states (`active`, `expired`, `revoked`); enforces TTL-based expiration and manual revocation without wall-clock dependency. |
| **Unified Access Module** | `access-module.mjs` (`ZetroAccessModule`) | Composition of the four providers above | Exposes high-level orchestration (`createAuthenticatedSession`, `authenticateToken`, `authorizeCapability`); verifies session vitality before allowing token claims. |
