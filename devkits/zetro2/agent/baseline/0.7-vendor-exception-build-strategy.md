## 1. Assist Architecture Rules Context

The Codexsun repository enforces rigorous structural and operational rules (`assist/governance/repository-architecture-rules.md` and `assist/governance/coding-agent-rules.md`):
1. **Mandatory File Limit:** "Every authored file must contain 700 lines or fewer. Split a file by a meaningful module concern before it exceeds the limit. Do not bypass this rule with generated code, copied files, or compressed formatting."
2. **Workspace & Dependency Rule:** "Install dependencies only in the root `node_modules/` directory. Do not create nested `node_modules/` directories in applications, packages, modules, or tools."
3. **Artifact Boundary Rule:** "Write all build artifacts only to the root `dist/` directory. Local `dist/` directories are prohibited everywhere below the repository root."
4. **Module Boundary Enforcement:** Every module under `src/modules` must have a `provider.ts`, `README.md`, declare its owner, and avoid private cross-module imports (`tools/check-module-boundaries.mjs`).

The imported editor tree (`devkits/zetro2/zvcode/`), comprising 9,280 files and ~171MB derived from OpenVSCode Server 1.110.0, includes large upstream files exceeding 700 lines and its own Gulp/npm dependency structure. Without an explicit, documented exception and strategy, this would conflict with automated repository audits.

## 2. The Vendor-Source Exception Definition

### 2.1 Scope of the Exception
The vendor-source exception is **strictly and exclusively confined** to the directory:
```text
devkits/zetro2/zvcode/
```

### 2.2 What the Exception Grants within `zvcode/`
- **File Length Exemption:** Existing upstream files (e.g. `src/vs/workbench/browser/parts/editor/editorPanels.ts`, `build/gulpfile.compile.ts`) may exceed the 700-line authored limit without requiring artificial splitting that would break upstream patch compatibility.
- **Upstream Directory Layout:** Retention of upstream VS Code structure (`build/`, `src/vs/`, `extensions/`, `test/`).
- **Upstream Packaging Manifests:** Retention of upstream `package.json`, `package-lock.json`, and `.nvmrc` (`22.22.0`).
- **License & Notice Preservation:** Retention of upstream `LICENSE.txt` and `ThirdPartyNotices.txt`.

### 2.3 Strict Prohibitions (No Bypass)
- **Zero Extension to Authored Code:** The exception does **NOT** apply to any Zetro2-authored code outside `zvcode/`. All code in `devkits/zetro2/api/`, `devkits/zetro2/web/`, `devkits/zetro2/editor/`, `devkits/zetro2/zbrowser/`, and `devkits/zetro2/agent/` must strictly adhere to the 700-line ceiling, module boundary requirements, and linting rules.
- **No Host-Side Dependency Installation:** Running `npm install`, `npm ci`, `yarn`, or `pnpm` directly inside `devkits/zetro2/zvcode/` on the host is strictly prohibited.
- **No Committed Build Outputs or Nested Node Modules:** Nested `node_modules/` or local `dist/` must never be created or committed inside `zvcode/`.
- **No Direct Package Inclusion in Root Workspaces:** `devkits/zetro2/zvcode` is intentionally omitted from the root `package.json` `workspaces` array.

## 3. Upstream Dependency and Build Strategy

### 3.1 Container-Isolated Compilation
To ensure host environment stability, cross-platform compatibility, and strict adherence to root layout rules:
- **Build Container:** All editor compilation, dependency installation, and packaging tasks are performed inside an isolated Docker build container (`devkits/zetro2/.container/Editor.Dockerfile`).
- **Toolchain Pinning:** The container provides pinned Node 22.22.0, Python 3, and native C++ build tools required by VS Code native modules (node-gyp, keytar, node-pty).
- **Host Cleanliness:** The host source tree remains completely unmodified during builds. No host files outside the target output path are created or touched.

### 3.2 Artifact Management
- **Single Root Dist Rule:** Any build outputs extracted to the host must target:
  ```text
  dist/zetro2/editor/
  ```
  or be packaged directly into a Docker image layer.
- **Turborepo Integration:** Turborepo caching for Zetro2 workspaces (`@codexsun/zetro2-api`, `@codexsun/zetro2-web`) is strictly directed to `dist/.turbo/`.

### 3.3 Integrity Verification
The repository maintains an automated verifier to ensure the vendor exception remains cleanly scoped and branding/licensing requirements are upheld:
```powershell
node devkits/zetro2/editor/verify-zvcode.mjs
```
This check verifies:
1. Product branding (`product.json` values for `nameShort`, `nameLong`, `applicationName`, `serverApplicationName`, `dataFolderName`).
2. Package root identity (`name: "zvcode"` in `package.json` and `package-lock.json`).
3. Gulp packaging hook integration.
4. Exact match of license and third-party notices against the reference upstream source.
