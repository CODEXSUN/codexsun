## 2. Invariants & Security Guardrails

1. **Session Expiration & Token Verification:**
   - Every authenticated request verifies the token against JWT secret and checks session active status in `SessionProvider`.
   - Past TTL expiration (verified with deterministic `createTestClock`), requests are rejected with 401 Unauthorized.
2. **Explicit Logout & Token Invalidation:**
   - On logout, the session is marked as revoked (`manual_logout`). Subsequent requests using that token fail with 401.
3. **Workspace Switching Isolation:**
   - Users can only switch to workspaces where they hold active membership. Switching issues a new scoped token reflecting the user's role and capability grants in the target workspace.
4. **Role Hierarchy & Membership Invariants:**
   - Only roles with `membership.manage` capability (Owner) can invite members or update roles.
   - Actors cannot assign roles equal to or higher than their own rank (`canAssignRole`).
   - Workspaces must retain at least one Owner (cannot remove the last Owner).
5. **Audit Logging & Redaction:**
   - Every auth and membership action (`auth.login`, `auth.logout`, `workspace.select`, `workspace.create`, `membership.add`, `membership.update_role`, `membership.remove`) records an audit event with sensitive data automatically redacted.
