## 5. Storage, Volumes, and Isolation Boundaries

### 5.1 Docker Volume Architecture
As defined in Compose (`devkits/zcode/.container/docker-compose.yml` and Zetro2 architecture):
- `workspace-data`: Persistent volume mounted at `/home/workspace` or `/workspace`, containing the checked-out repository. Shared among editor, agent backend, and Zbrowser runners.
- `editor-home`: Dedicated volume mounted at `/home/openvscode-server` for user settings, workbench state, and extensions.
- **Security Constraints:**
  - `no-new-privileges: true`
  - `cap_drop: [ALL]`
  - Explicit non-root execution (`user: node` or dedicated openvscode user).
  - **Docker Socket:** Strictly prohibited from being mounted inside editor, agent, or preview containers.
  - **Control Plane Isolation:** Running control service code and credentials must remain strictly separate from the editable working checkout.

### 5.2 Host Filesystem Boundaries
- **Artifacts & Output:**
  - Build outputs strictly confined to root `dist/` (e.g. `dist/devkits/zetro2/web/`, `dist/zetro2/`).
  - Local workspace `dist/` directories are prohibited and enforced by repository checks.
  - Turborepo caches scoped to `dist/.turbo/`.
- **Private State:**
  - Scoped to `storage/apps/private/zetro2/` (for SQLite databases, migrations, execution logs, and run artifacts).

## 6. Shared Identity & Access APIs Inventory

### 6.1 Package: `@codexsun/platform-core`
The central library provides public, reusable authentication, authorization, and persistence primitives:

1. **Identity Contracts (`identity-contracts.ts`):**
   - Zod schemas: `actorSchema`, `actorKindSchema` (`user` | `service`), `roleSchema`, `permissionSchema`, `identitySessionSchema`, `sessionStateSchema` (`active` | `revoked`), `authorizationRequirementSchema`.
   - Core function: `authorize(actor: Actor, requirement: AuthorizationRequirement): AuthorizationDecision`
     - Evaluates whether an actor holds required permissions.
     - Supports `*` full wildcard and fine-grained permissions.
2. **Identity Configuration (`identity-configuration.ts`):**
   - `readLocalIdentityConfiguration(env, options)`: Validates JWT secrets (`PLATFORM_JWT_SECRET`), sets lockout thresholds, rate-limits, seed credentials (super-admin, admin, user), and database path.
3. **Local Identity Engine (`local-identity.ts`):**
   - `createLocalIdentityManager(config)`:
     - SQLite-backed user, role, permission, and session manager using Node.js built-in `node:sqlite` (`DatabaseSync`).
     - Includes checksummed migrations (`identity.001` through `identity.005`).
     - Secure password hashing with PBKDF2/SHA-512 and timing-safe verification.
     - Session issuance with signed JWT tokens (`createPlatformJwtToken`, `readPlatformJwtClaims`).
     - Session revocation (`revokeSession`) and active session lookup (`readActiveSession`).
4. **Data & Migration Infrastructure:**
   - `sqlite-data-provider.ts`: Typed SQLite data provider.
   - `migration-runner.ts` & `migration-integrity.ts`: Serial, checksummed, append-only migration engine.
   - `database-outbox.ts`: Outbox pattern for reliable domain event dispatching.

### 6.2 Zetro2 Identity Blueprint (Phases 1–3)
- Zetro2 will leverage `@codexsun/platform-core` contracts without importing private cross-app files.
- **Workspace Roles:** Owner, Maintainer, Developer, Reviewer, Viewer.
- **Scoped Capabilities:** `workspace.read`, `workspace.write`, `process.execute`, `agent.run`, `change.approve`, `git.commit`, `git.push`, `provider.manage`, `mcp.manage`, `browser.use`, `computer.use`, `membership.manage`.
- **Database Scope:** Scoped private SQLite database at `storage/apps/private/zetro2/zetro2_db.sqlite`.
